# Pre-use rescue

The recovery API in `service/rescue.ts` supports `RESCUE_MODE=fork` with loopback RPC overrides for isolated tests and `RESCUE_MODE=production` with `https://evm.stupidtech.net/v1/<chainId>`. The relayer key is a Cloudflare Worker secret. The browser recovery flow is served at `/recover`. Each request supplies a chain ID; the service checks the actual chain ID, pinned CREATE2 factory code, parent-bound delegate identity, agent nonce and pointer, and current gas before action. A missing or incompatible factory fails closed. The Ethereum and Base fork integrations exercise the full rescue; two small-value pre-use rescues have also completed on public Base.

## Parent session and discovery

1. `POST /api/session/challenge` with `{ address, chainId }` returns an EIP-4361 SIWE message with an origin-bound nonce and five-minute expiry.
2. The wallet signs the message with `personal_sign`. `POST /api/session` verifies it on the selected chain (EOA or ERC-1271), consumes the nonce, and sets a 15-minute HttpOnly, SameSite=Strict cookie. A replayed signature cannot open another session.
3. `GET /api/parents/accounts` lists only agents linked to that parent. Signed 7702 authorizations remain server-side and are never included in responses.

## Native-asset rescue

The web app starts recovery from a selected linked agent, recipient, and native amount; no rescue ID is needed to begin. For a pre-use agent, `Start recovery` creates a quote and shows its ID for later continuation. `Resume a pre-use recovery` is an optional disclosure for an interrupted quote. An already-active agent instead uses `Recover assets` to send the parent-wallet rescue transaction directly.

1. `POST /api/rescues` with `{ agent, chainId, recipient, amountWei }` requires a parent session on that chain. It checks the parent association, agent balance, nonce/code, verified CREATE2 factory, and delegate identity. Pre-use funding currently requires a **direct EOA parent payment**; smart-wallet funding fails explicitly. Already-active agents can be rescued directly by the parent from `/recover`, including a smart-wallet parent.
2. The quote returns a relayer address and exact `fundingWei` calculated from current maximum fee per gas, bounded deployment/activation gas limits and a small additional data-fee reserve. **The payment is non-refundable.** Unused funds stay with the relayer, including after a failed attempt. The quote expires after ten minutes; gas changes or unusual chain fee models can still exceed it. If the relayer needs more gas, the browser lets the parent top it up and resume the same quote and persisted raw transaction.
3. The parent sends a native-asset transfer of exactly `fundingWei` to the relayer. `POST /api/rescues/:id/activate` with `{ fundingTxHash }` verifies the sender, recipient, value, calldata, receipt, and two canonical block confirmations. It locks the quote, revalidates the nonce/delegate, and persists each signed deployment/activation raw transaction **before** sending. Repeating the same request resends or checks the same hash; a pending step returns `activating`. Once both transactions have canonical receipts, it verifies the runtime, pointer, bound parent and receipts before returning `active` or `active_partial`. The browser allows resuming with the rescue ID and funding hash. No automatic gas-price replacement is provided for stuck transactions.
4. The parent calls `executeBatch` from their own wallet to transfer the quoted native amount to the quoted recipient. `POST /api/rescues/:id/complete` with `{ rescueTxHash }` checks the sender, exact calldata, successful receipt, two canonical confirmations and current delegation before reporting `completed`. `GET /api/rescues/:id` shows the quote and transaction status within the same parent session. The browser allows completing with an existing rescue hash so a retry does not send the transfer twice. Status returns a typed `errorCode` and a message derived from it; raw RPC errors and signed transactions are not returned or stored as error text.

The production relayer key is a Cloudflare Worker secret; its local backup is outside the repository at `~/.local/share/agent-wallet/relayer.json` with owner-only permissions. The `test:rescue` runner generates a **different** key in memory, writes it only to a mode-0600 temporary `.dev.vars`, creates isolated local D1 state, and removes the files afterward. It never uses the agent key after onboarding. Run with Bun and Anvil installed:

```sh
bun run test:rescue
```

The test signs in via SIWE, rejects wrong signatures and funding, exercises a recoverable underfunded relayer with an error code, proves that the same stored nonce-0 authorization activates each fork, and confirms native-asset rescue. The public Worker and D1 are deployed at `https://agent-wallet.stupidtech.net` (version `772d2ef4-c27b-4016-b31c-efd1b649554f`). On public Base, a txlink-approved CREATE2 deployment of one parent-specific delegate was source-verified at BaseScan. Two agents with that parent completed pre-use rescue using the saved nonce-0 authorization without agent signing after onboarding. The first quote revealed an additional Base data fee and required a small parent top-up; the second completed with the revised reserve and no top-up. Both test agent balances were zero after rescue. Public missing-delegate relayer deployment, public first-use agent transactions, live ERC-1271 onboarding, smart-wallet pre-use funding, and automatic replacement of stuck relayer transactions have not been verified or implemented.
