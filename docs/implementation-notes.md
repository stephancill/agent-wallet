## Change log

- Established the engineering handover and root agent instructions. No onchain recovery or transaction flow has been verified yet.
- Verified against Ethereum and Base forked live state: identical deployed factory bytecode, fork-only bootstrap replay, identical CREATE2 delegate runtime/address, lost-key parent-funded pre-use ETH rescue, and separate agent-funded nonce-0/type-4 first use with authorization nonce 1. Tested wrong-parent initialization/revert persistence, direct initialization, revert of oversized rescue, and nonce drift invalidating the stored authorization. The transactions were mined locally on Anvil forks; no public rescue was performed. See `protocol-spike.md` for evidence and remaining production gates.
- Earlier iteration: implemented a bespoke EIP-7702 delegate with EOA-key-authenticated cross-chain parent initialization, namespaced storage, agent-signed atomic batches bound to account/chain/implementation/calls/nonce/preparation/expiry/gas floor, parent direct execution, reentrancy protection, and EOA-key ERC-1271 validation. That design was superseded; its tests and signatures no longer apply.
- Earlier iteration: verified the bespoke bytecode on Ethereum and Base Anvil forks with the same CREATE2 address/runtime, pre-use rescue and agent-signed relayed batch. This identity was superseded and was never deployed publicly. The current fork runner patches the compiler artifact's runtime immutable placeholders with the **parent address** before comparing hashes.
- Earlier iteration: replaced the bespoke delegate with an extension of pinned eth-infinitism `@account-abstraction/contracts@0.8.0` `Simple7702Account`. It added parent initialization and access to inherited execution, while removing the extra relayed operation signature. This design was superseded by the standalone constructor-bound contract; its dependency has been removed and its address and signatures must not be used.
- Earlier iteration: verified the extended Simple7702 bytecode on Ethereum and Base Anvil forks with pre-use rescue and agent-funded first use. Its common CREATE2 address was never deployed publicly and was superseded by the parent-specific identity in `production-account.md`.
- Replaced the extended Simple7702 variant with a standalone parent-specific delegate. The constructor requires a nonzero parent and embeds it in CREATE2 initcode and runtime; the parent can call an atomic batch directly and the agent EOA can call itself. There is no initializer, storage, EntryPoint, custom operation signature, or contract-level nonce. OpenZeppelin supplies ECDSA, low-level call/revert bubbling, and ERC-721/1155 receivers. Removed the unused account-abstraction dependency. This is a breaking change to the earlier local delegate address, signed authorization, initializer API and common-address assumption; no public accounts used them. The parent must be known before signing the nonce-0 rescue authorization, and txlink must calculate the parent-specific delegate before collecting request-bound consent.
- Verified on Ethereum and Base Anvil forks with one ephemeral parent: identical parent-specific CREATE2 initcode/address/runtime across both, nonce drift invalidating the saved authorization, reverted execution leaving the pointer installed **and parent rescue succeeding afterward**, parent-funded pre-use rescue after the agent key is no longer used, and separate agent-funded type-4 first use followed by self-batch. Nine Foundry tests cover constructor/address binding, authorization, atomic rollback, ETH/ERC-20/ERC-721/ERC-1155 rescue, smart-wallet parent calls and ERC-1271. See `production-account.md` for sample ephemeral identity, local transaction IDs and reproduction. No public deployment or independent audit has occurred.
- Revised the planned service boundary: Agent Wallet will have its own browser approval URL, frontend, HTTP API, durable database, and relayer. The API will own parent-consent verification, associations, rescue artifacts, transaction preparation/broadcasting, and recovery. txlink remains optional for short-lived ordinary payment approval links; its generic public seven-day request records do not establish consent or custody. This supersedes the txlink service assignment in earlier notes. Updated the handover, contract notes, protocol-spike delivery-gate wording, and repository instructions. This is a documentation/architecture decision only; no frontend, API, CLI, integration, or public deployment was implemented or verified.
- Implemented a local onboarding vertical slice: a generated, checked-in delegate identity derived from the Foundry artifact; a Worker/D1 login-attempt/account schema; agent-signed login/finalize challenges; a bespoke React wallet approval page; viem EIP-712 EOA/ERC-1271 verification; an owner-only local CLI key with retryable login; and server-verified chain-agnostic nonce-0 authorization storage. Read-only Ethereum/Base status distinguishes pre-use eligibility, verified activation, and unavailable chain state. The artifact is withheld from GET responses and txlink is not involved. Unit identity/signature tests and local Worker/D1 integration (including the real CLI) passed against Ethereum/Base live read endpoints with ephemeral EOAs. No transaction was broadcast; ERC-1271 positive-path onboarding, public deployment/source verification, relayer rescue and normal operations have not been verified or implemented. See `onboarding.md` for reproduction.
