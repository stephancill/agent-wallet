# Implementation notes

## Current state

- A reproducible two-chain protocol spike is in `scripts/spike.ts` with its deliberately minimal `src/SpikeDelegate.sol` fixture. The production-intended account delegate is `src/AgentAccount.sol`, with unit tests and a separate Ethereum/Base fork runner in `scripts/account-fork.ts`. The Bun CLI, Vite/React approval/recovery page, and Worker/D1 API implement onboarding, locally signed transaction preparation/broadcast and EOA-parent-funded native-asset rescue. The Worker/D1 are publicly deployed; live ephemeral-account onboarding, two small-value public Base rescues, and agent-funded first use plus batch execution on public Base and Optimism have passed, including a relay bridge. Transaction and rescue end-to-end tests also passed on Ethereum/Base/Optimism forks. Parent-specific delegates are source-verified on Base; `@stupidtech/agent-wallet@0.1.0` is published on npm, and the agent skill is in `skills/agent-wallet`.
- The agreed product scope, flow, constraints, and validation gates are in `engineering-handover.md`.
- `protocol-spike.md` records the fork method, code/deployment hashes, sample local transaction IDs, verified behaviors, and limits.
- `production-account.md` describes the current standalone parent-bound delegate, per-parent deployment identity, verification steps, and remaining release gates.
- `onboarding.md` documents the local API/frontend/CLI flow, run commands, and remaining release gates.
- `recovery.md` documents the public and fork SIWE session and pre-use rescue flow, non-refundable funding quote, verification, and remaining gates.
- `transactions.md` documents the CLI batch format, phased service protocol, local verification and remaining gates.
